## 两种窗口

**管理主窗口**负责找资源、设置共享和查看传输。侧栏只有三个常用入口：
我的资源、本机共享、文件传输。个人账号不展示管理员功能。

**Session 窗口**只负责当前连接。它没有管理侧栏，也不把远程画面缩进
一个后台页面。连接状态、声音、剪贴板、传输和全屏操作放在紧凑工具条中。
连接面板默认收起，第四张画稿展开它，以便讨论具体内容。

关闭 Session 只结束该连接。关闭管理主窗口不等于停止被控服务；
停止共享是“本机共享”里的独立操作。退出账号需要明确提示本机共享
和当前连接会受什么影响，不能悄悄断开。

## 主要操作

资源首页点“连接”或“启动”，打开独立 Session；已连接资源显示“返回会话”，
不重复创建连接。点资源名称进入详情。应用卡片突出应用名称和共享者，
不要求使用者先选择承载它的电脑。

“本机共享”面向设备所有者。桌面授权与单应用授权分开，发布应用时需要选择
应用、指定用户、确认允许的功能，再发布。未授权的用户看不到资源。

文件沿用目前产品行为：复制本地文件或拖入会话窗口后发送，
接收文件保存在 Downloads/NebulaDesk。不能把界面画成“已复制文件后，
任意远程目录粘贴”却在实现中悄悄改为自动下载。

## 需要保留的状态

| 场景 | 界面行为 |
| --- | --- |
| 第一次登录，没有设备 | 说明如何添加自己的电脑；别人共享的应用会自动出现在这里 |
| 设备离线 | 保留卡片和最后在线时间，不提供无效的连接按钮 |
| 系统权限不足 | 本机共享中逐项指出缺少的权限，给出前往系统设置的入口 |
| 正在建立连接 | Session 显示连接进度与取消操作，尚未成功时不显示绿色状态 |
| 直连切回中继 | 保留窗口和远程画面，状态改为“中继连接”，不要求重新打开 |
| 所有可用路径均失效 | 明确显示已断开；“重新连接”发起新连接，不伪装成已恢复 |
| 授权被撤销 | 不再允许申请新会话；目标是同步结束现有连接，但实时撤销链尚未实现，当前界面须明确说明 |
| 文件传输失败 | 显示失败原因和重试入口，不把发送完字节当作接收成功 |
| 停止本机共享 | 若有人正在使用，先展示受影响的连接并确认 |

## 视觉基线

浅灰底色、深蓝主操作，绿色只表示在线或就绪。常规正文 13–14 px，
页标题 28 px，卡片圆角 8–12 px，侧栏宽 224 px。设备封面是示意插画，
不是悄悄采集的远程桌面缩略图。

先以 macOS 窗口结构讨论，Windows/Linux 保留平台自身的标题栏按钮与快捷键。
不会在 Windows 照搬红黄绿窗口按钮或 Command 快捷键。

## 与现有代码的边界

原生会话、传输与权限策略已有基础。管理主窗口、图形化授权、应用发布配置、
多窗口协调和 Session 工具条按本稿实施；具体可用范围以根 README 和实际界面为准。
单应用窗口串流仍需后端支持，发布配置不等于已经可以串流应用。

本轮不扩展管理员 Web 控制台。登录、添加设备、授权编辑、文件传输详情
和异常状态沿用本稿的视觉规范，不依赖设计中的样例数据。
